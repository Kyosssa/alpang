## 1. [치명] `/npcs/#quest-*` 90초 프리징 — 해결
**원인 확정.** `npcs/index.html`의 `goHash()`가 대상 앵커가 없으면 `loadRest().then(goHash)`를 호출하는데, 나머지 NPC를 이미 불러온 뒤에는 `loadRest()`가 즉시 이행되는 Promise를 돌려줍니다. 그래서 `goHash → Promise.resolve().then(goHash) → …`가 마이크로태스크로 끝없이 이어지고 이벤트 루프가 양보하지 못해 화면이 멈춥니다(수정 전 로직을 별도 시험하면 반복 상한 20만 회에 곧바로 도달). 실제 앵커가 없는 링크가 있어서 드러났습니다.
- ① **가드:** 대상이 없으면 나머지 NPC를 **한 번만** 불러 재시도하고 그래도 없으면 즉시 중단(`hashTried`/`restLoaded`). 잘못된 셀렉터(`#quest-*` 같은 형태)는 `try/catch`로 무시. 로드 실패 시 `apply()`가 재시도를 반복하지 못하게 `restFailed` 플래그 추가. 빌더(`npc_quest_build_unified.py`)에도 역이식.
- ② **링크 139건 수정:** `guide/early-quests`의 `/npcs/#quest-N` 139건(고유 59개 퀘스트) → `/quests/lv-*#quest-N`. 59개 모두 `quests/lv-*` 중 정확히 1곳에만 앵커가 있음을 확인했고(`lv-11-20` 30·`lv-21-30` 16·`lv-1-10` 9·`lv-41-50` 3·`lv-31-40` 1), 잔존 `/npcs/#quest-` 링크는 0입니다. 디렉터 메모의 `/quests/lv-*/#quest-*`는 실제 페이지가 `lv-1-10.html`(확장자 없는 `/quests/lv-1-10`)이라 이 형태로 맞췄습니다.
- **같은 패턴 점검:** 사이트 전체에서 `/npcs/#quest-`는 이 페이지뿐이고, `/npcs/#npc-*` 참조 고유 824개는 `npcs/index.html`+`npcs-rest.json`에 전부 존재합니다(누락 0).
- **시험(브라우저):** `/npcs/#quest-2105`로 진입해도 응답 지연 2ms, 나머지 NPC는 1회만 로드(카드 1,836). 해시를 `#npc-9901919`(나머지 쪽 NPC)로 바꾸면 카드가 열리고, `#quest-*`·`#quest-99999`는 예외·멈춤 없이 통과.
- ※ `early-quests` 페이지는 저장소에 생성 빌더가 없어 정적 수정만 했습니다(빌더 위치 확인 필요).

## 3. `/mobs/` '더 보기' 카운터 — 해결
**원인 확정.** 스크립트는 정상입니다. `.qmore{display:block}`이 `hidden` 속성(UA 스타일)을 덮어써서, 필터 결과가 50건 이하이거나 0건이어도 `more.hidden=true`가 화면에 반영되지 않고 직전 문구('남은 138건')가 그대로 보였습니다. 수정 전 재현값: 결과 0건에서 `hidden=true`·`display:block`·문구 '남은 138건'.
- 수정: `.qmore[hidden]{display:none}` 한 줄. 시험: 0건·1건 `display:none` / 초기화 시 복귀 / '더 보기' 1회 후 '남은 88건'(100개 표시) / 레벨 칩 1~30(53종)에서 숨김.
- **범위 확장(요청 외):** 같은 `.qmore` 규칙이 동일한 문자열로 **14개 페이지**(`mobs`·`jobs`·`npcs`·`quests/*` 11)에 있어 모두 같은 결함이 있으므로 함께 고쳤습니다. 빌더 3종(저스티스 도감·직업·NPC/퀘스트)에도 역이식. 되돌리려면 `.qmore[hidden]` 줄만 지우면 됩니다.
