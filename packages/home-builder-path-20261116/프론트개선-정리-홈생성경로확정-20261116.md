# 프론트개선 정리 — 홈 생성 경로 확정 (Claude 종결 열린 조건)

## 생성 경로 결론

- **홈은 전용 생성 빌더가 없다.** 홈 정본은 로컬 `site/index.html` (40,540B · 732bebc1…)이며, 동결 · 배포 때마다 이 정본 세대가 저장소로 나가는 정적 관리 방식이다.
- `home_build.py` (14,509B · fa79653e…)는 홈을 생성하는 빌더가 아니라, 정본 site/index.html에서 템플릿 (templates/home.html)과 다국어 사전을 추출하는 **다국어 파생용 빌더**다. 정본이 바뀌면 템플릿 추출이 다시 돌아야 하는 구조다.
- 배포본 지위: 저장소 정본 index.html (37,542B · b51fe6cc… — 결함 정정 배포 세대). 로컬 정본과 2,998B 세대 차이가 있어, 다음 홈 동결에서는 어느 세대가 현행인지 대조가 선행돼야 한다 (사전 점검 목록 1번 지점).

## 로컬 정본 결함과 정정안 (동결 절차로 별도 진행)

- 로컬 정본 실측: CF 변환 링크 1개 · 빈 Analytics 주석 7개 · mailto 0 — 저장소에서 정정된 것과 같은 결함이 정본에 남아 있다.
- 정정안: ① 문의하기 CF 링크 → mailto 복원 ② Analytics 주석 7개 제거. 저장소 정정 (b51fe6cc…)과 같은 처방이다.
- 적용 조건: 세대 대조로 로컬 정본이 현행임이 확정된 뒤, 동결 목록 → 검수 QA → 배포 (로컬 정본 교체 포함) 순서로 따로 간다. 이 정리 문서 자체는 정정 · 배포를 실행하지 않는다.

## 이후 홈 작업의 기준

- 홈 동결의 기준본은 저장소 정본 (API contents 기준 — raw CDN 캐시 시차 회피).
- 정본 교체가 일어나면 home_build.py 템플릿 재추출 필요 여부를 함께 확인한다.
